# 音视频转笔记

将用户提供的链接、音视频文件或逐字稿，整理成符合用途、忠于原素材、可独立阅读的成果。按用户要求决定范围；使用当前环境可用的工具，不能假定特定 Agent、操作系统、NAS 或模型服务存在。

## 确定交付物

用户明确了笔记类型就直接执行；不明确时询问一次：逐字稿、详细整理、重点摘要、专题整理、会议纪要，或用户自定义类型。不要把素材类型等同于用户想要的笔记类型。详略默认由交付类型及素材决定；用户的要求优先。参见 [笔记类型](references/note-types.md)。

默认交付普通 Markdown 和所需图片，使用相对路径引用。原素材、逐字稿、成品和中间文件各自区分；遵循用户指定的保存位置与同步要求。仅要求逐字稿时，不自动生成笔记、配图或外部研究。用户指定不联网或不配图时遵从。

## 工作流程

1. **识别入口与环境**：接受链接、本地音视频或已有逐字稿。查看可用的下载、转写、媒体检查、图像查看和网络工具。需要的能力缺失时说明影响及替代途径。平台链接按需读 [平台索引](references/platforms/README.md)。
2. **获取并核对素材**：按用户授权获取文件，记录标题、来源、链接和可得的时长等信息；检查文件能否解码及是否完整。无法下载时说明原因，提供用户能自行取得文件或提供逐字稿等选项。不要推测绕过付费、访问控制或验证。
3. **转写与核对**：先检查是否已有可信字幕或用户提供的逐字稿；需要转写时引导优先使用合适的本地模型。评估语言、质量、速度与资源；本地不适合时说明云端选择、上传内容及可能费用，按用户已授权的配置使用。保留带时间的原始转写；检查覆盖、缺段、重复及关键人名、数字、术语；不确定时回听并标注，不能凭猜测改写。详见 [转写](references/transcription.md)。
4. **理解与整理**：完整了解素材范围，依据要求提取观点、过程、例子和限制。区分事实、发言者观点与推断；不能确定发言者时不猜姓名。材料过长时分段处理，最后检查跨段连续性和结尾覆盖。
5. **视频图文结合**：笔记类任务默认查看原视频，寻找对理解有实质帮助的画面；按时间戳回看、筛选清晰完整的截图，置于相关文字附近并解释。数量不限；没有有效画面就不强加。无法查看视频或提取画面时明确报告，不把候选帧当作已核验配图。详见 [视频配图](references/visual-notes.md)。
6. **学习类内容查资料**：默认查询有理解门槛的概念，可补充有帮助的背景与延伸；优先可靠原始来源。区分素材原意和外部补充，在相关内容附近给出可追溯来源；外部图片记录来源、作者及许可。无法联网时说明未完成，不能编造来源。详见 [资料查询](references/research.md)。
7. **交付检查**：核对笔记与素材的关键事实、时间码、图片内容及相对链接；检查截图可读性、来源、未解决的不确定性。说明实际完成的步骤、未完成的环节和结果位置；不要将结构检查或模型输出等同于逐句人工核验。

## 凭据、隐私和副作用

登录由用户在平台界面完成；优先复用用户明确授权的受控会话。登录状态和 Cookie 是凭据，不要求用户粘贴到聊天，不写入笔记、日志、示例或公开包。处理私人素材时，向外部服务传输前应确认用户已授权该服务和数据范围；同步、分享、发布和覆盖已有文件按用户授权执行。长任务汇报真实状态，完成前不声称已完成。
